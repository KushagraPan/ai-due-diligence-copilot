# Preflight Audits & Verification Layer

This document details the **Preflight Audit System** in the AI Due Diligence Co-pilot: what the preflight files are, why they are generated, where the scripts that produce them are stored, and how they guarantee zero silent data loss before embedding and indexing.

---

## 1. Executive Summary & Core Purpose

In corporate due diligence, ingesting documents (such as a 678-page annual report or 10-K filing) through naive parsing pipelines frequently leads to **silent data loss**:
- Multi-column narrative text is flattened out of reading order.
- Financial tables lose column alignment or are parsed as disconnected text snippets.
- Text surrounding tables is either double-ingested or wiped out by bounding box collisions.
- Thousands of expensive multimodal LLM calls are wasted on simple, clean pages.

The **Preflight Audit System** operates like an aviation pre-flight checklist: before any text or table is vectorized or ingested into Weaviate, the complete document undergoes full-corpus deterministic preflight scans.

These scans produce machine-readable, persistent audit records in `data/processed/` that prove:
1. **Mathematical Completeness:** Every block of text in the PDF is assigned to exactly one structural element (zero unowned blocks, zero double-counted blocks).
2. **Tabular Quality & Routing:** Every tabular region is evaluated against an objective 5-point quality gate, triaging between fast local extraction (Tier 1) and multimodal vision fallback (Tier 2 Gemini Flash).
3. **Character Fidelity:** Raw character counts from the PDF text stream match structured extracted characters within strict tolerances, alerting developers to any lost content.

2. **[`scripts/run_layout_preflight.py`](../scripts/run_layout_preflight.py):**
   - **Command:** `uv run python scripts/run_layout_preflight.py`
   - **Function:** Scans all 678 pages, reconciles narrative text blocks against table bounding boxes, extracts captions and footnotes, clusters multi-column bands (left-to-right reading order), classifies headings and list items, verifies block ownership invariants, and exports `layout_preflight_2026-09-25.json`.
   - **Execution Time:** ~23–25 seconds across 678 pages.

3. **Auxiliary Diagnostic Scripts in [`scripts/`](../scripts/):**
   - [`scripts/audit_symbol_fonts.py`](../scripts/audit_symbol_fonts.py): Scans for non-standard symbol fonts and verifies glyph mappings in `config/symbol_font_mappings.yaml`.

## 3. Schema & Field Definitions

### 3.1 Table Preflight Schema (`table_preflight_2026-09-25.json`)

The table preflight artifact contains a top-level `summary` block followed by a `pages` array with 678 per-page records:

```json
{
  "summary": {
    "total_pages": 678,
    "table_detected_pages": 517,
    "narrative_only_pages": 161,
    "total_table_regions": 747,
    "tier1_passed_tables": 424,
    "tier2_routed_tables": 323,
    "continuation_tables_detected": 16
  },
  "pages": [
    {
      "page_number": 381,
      "table_detected": true,
      "table_region_count": 1,
      "tier1_extracted": true,
      "extracted_row_count": 31,
      "extracted_column_count": 3,
      "row_consistency": 1.0,
      "fragmented_word_count": 0,
      "continuation_detected": true,
      "gate_passed": false,
      "tier2_routed": true,
      "failure_reasons": ["continuation_detected (unstitched predecessor page 380)"]
    }
  ]
}
```

#### Table Quality Gate Rules
A table extracted in Tier 1 passes the quality gate and bypasses Tier 2 vision if and only if all of the following hold:
1. `extracted_column_count >= 2`: Rejects single-column boxed text callouts.
2. `extracted_row_count >= 2`: Rejects single-line isolated headers or footers.
3. `row_consistency >= 0.85`: At least 85% of body rows must match the dominant column count.
4. `fragmented_word_count == 0`: Zero words split into fragments by superscript footnotes or font issues.
5. `continuation_detected == false`: If a table lacks headers and continues an unclosed financial statement from the preceding page (e.g., Page 381 Cash Flow), it is flagged for stitching or Tier 2 verification.

#### Layout Mathematical Invariants
Every valid page must satisfy:
1. `unowned_block_count == 0`: **Zero dropped content.** Every PyMuPDF text block is assigned to Table, Heading, ListItem, or NarrativeText.
2. `multiply_owned_block_count == 0`: **Zero duplicate content.** No block is claimed by more than one category.
3. `owned_block_count == source_block_count`: Exact identity between source blocks and categorizations.

## 4. Key Preflight Findings Across the 678-Page Corpus

1. **424 Tables Extracted for $0 and <10 Seconds:**
   Tier 1 column-projection successfully passed 424 tables without requiring external API calls or latency, reserving Gemini Vision for the 323 complex or fragmented tables.
2. **Zero Block Ownership Violations (0 unowned, 0 conflicts):**
   Across all 678 pages, the spatial partitioning algorithm in [`src/due_diligence/ingestion/layout.py`](../src/due_diligence/ingestion/layout.py) achieved 100% mutually exclusive block assignment.
3. **Multi-Column Awareness:**
   308 pages (45.43% of the corpus) feature 2-column or 3-column layouts. The preflight verified that text blocks are sorted top-to-bottom within each column before advancing to the next, preventing cross-column text interleaving.
4. **Reconciliation Delta Causes Isolated:**
   - On table pages (e.g. Pages 380 and 470), the ~8% delta is 100% benign newline collapse from PyMuPDF's cell stream formatting, with 0 missing words.
   - On >20% delta pages (e.g. Pages 5 and 534), boxed narrative paragraphs or decorative borders triggered the table quality gate, successfully alerting developers via `needs_review=True`.

## 5. How Downstream Subsystems Consume Preflight Results

```
Preflight Verification Layer
(table_preflight.json & layout_preflight.json)
              │
              ▼
Phase 1 Task 4: Layout-Aware Chunking (src/due_diligence/ingestion/chunker.py)
   ├── Uses verified visual reading order from layout preflight
   ├── Keeps Table elements atomic with headers, footnotes, and captions
   └── Propagates verified section_heading and heading_path hierarchy
              │
              ▼
Phase 2: Vector & Hybrid Indexing (Weaviate Cloud)
   ├── Ingests chunks with exact provenance (page_number, bbox, doc_name)
   └── Zero corrupted or duplicated tables in vector storage
              │
              ▼
Phase 3 & 4: Diligence Agents & Citation Verifier
   └── Synthesizes answers with verifiable, audit-backed page citations
```
